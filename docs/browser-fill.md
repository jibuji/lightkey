# 浏览器填充通道规格（browser-fill，M3）

- 状态：已拍板（D12）；**协议本阶段落定，实现 V1 之后（M3）**
- 关联：[ipc.md](ipc.md)（守护进程通道）· [design/spec.md](design/spec.md)（填充 UI 约定）

## 1. 架构原则

- **扩展不持钥**：浏览器扩展零密钥、零凭据——它只是「遥控器」，密钥与解密
  全部在桌面守护进程侧。
- 通道：Chrome 官方 **Native Messaging**（扩展 ↔ 桌面已解锁会话）。
  - 扩展 ←Native Messaging→ 桌面应用（守护进程）—→ `lk-core` 解密取凭据。
- 扩展内存无密钥：任何密钥值不进入扩展进程内存，不进入页面上下文。

## 2. 填充流程

1. 用户在登录表单**主动点击**某输入框 → 扩展弹出填充候选（该站点的 login 条目）。
2. 扩展经 Native Messaging 请求守护进程：`fill.suggest(origin)` → 返回
   **最小字段**候选（条目名 + 用户名，无密码）。
3. 用户点击「填充」→ 守护进程解密取密码 → 经 Native Messaging 传回扩展 →
   填入用户点击的输入框（一次填充，值不缓存）。
4. 剪贴板（若用户选择复制而非填充）**30s 自动清除**。

## 3. 桌面未运行 / 锁定时的行为（D12）

- **填充置灰**：`vault.status` 非解锁 → 扩展 UI 填充项置灰（不隐藏入口，
  但不可用）。
- **快速解锁弹窗**：用户点击置灰项 → 唤起桌面快速解锁弹窗（小窗输主密码/
  生物识别）→ 解锁成功后原候选立即可填。这是缓解「桌面锁定则填充不可用」
  的主路径。
- 桌面完全未运行 → 扩展提示「请先启动 LightKey 桌面」并跳转。

## 4. 安全约束

- **只填充用户主动点击的输入框**：不做自动填充到任意字段、不自动提交表单。
- 候选匹配基于 origin（站点）→ 条目 uri 匹配；跨站候选不展示。
- Native Messaging host 清单限定本机唯一 host（`dev.lightkey.app`），
  manifest 白名单校验，防仿冒。
- 扩展与页面上下文严格隔离：填充值经扩展脚本注入，不注入页面可读的
  全局变量（使用隔离 shadow/自定义事件时避免泄漏给页面脚本）。
- 审计：填充动作（站点、条目 id、结果）写入守护进程审计；密钥值不明文。

## 5. 接口（本阶段落定，M3 实现）

```jsonc
// 扩展 → 守护进程
{ "method": "fill.suggest", "params": { "origin": "https://example.com" } }
// 返回：候选最小字段
{ "result": { "items": [ { "id": "<uuid>", "name": "示例", "username": "u@e.com" } ] } }

{ "method": "fill.retrieve", "params": { "itemId": "<uuid>", "field": "password" } }
// 返回：单次明文（仅当会话解锁且用户已点击）
{ "result": { "value": "s3cr3t" } }
```

- `fill.retrieve` 受解锁态 + 用户主动点击（扩展侧事件）双重约束。
- 错误码复用 [ipc.md](ipc.md) 约定（`session.invalid` 等），扩展统一置灰。
