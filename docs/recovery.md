# 恢复机制规格（recovery）

- 状态：已拍板（D9）
- 关联：[crypto.md](crypto.md)（K_recovery / 信封）· [data-model.md](data-model.md)
  （信封对象）· [ipc.md](ipc.md)（解锁）

## 1. 三通道模型（诚实边界）

用户持有三样东西，全丢则**数据不可恢复**（诚实文案，明示于 UI，不做安慰性承诺）：

1. **主密码**（记忆）
2. **恢复码**（备份凭证，见 §2）
3. **已信任设备**（生物识别宽限入口，见 §4）

> 若三者全丢（主密码忘 + 恢复码丢 + 无已信任设备），密文在数学上不可破解，
> 数据无法恢复。产品文案必须如实说明，不得暗示客服可找回。

## 2. 恢复码（D9）

- 生成：**高熵 40 字符**备份凭证（如 5 组 × 8 字符，base32 风格防混淆字符集）。
- 展示：`lk init` / 首次设置时**仅展示一次**，用户自行抄存/保存到密码管理器；
  应用**不记忆、不重新展示**（仅提示「已保存则跳过」）。
- 用途：配合新设主密码完成恢复（§3）。
- 校验：恢复码共 40 字符 = 39 随机字符 + 1 校验位，按校验位快速发现抄写错误。

## 3. 恢复信封（D9）

- 信封 = `recovery.envelope`：**恢复码 + Argon2id 派生信封密钥** 加密的
  **主密钥副本**（K_recovery 见 [crypto.md](crypto.md) §2）。
  - 信封密钥 = Argon2id(恢复码, salt=信封内随机 16B, m/t/p 同 vault 主 KDF)。
  - 载荷 = 加密的 MK + KDF 参数引用（便于升级重加密）。
- 信封**可随库进 BYO 云**（不影响零知识：信封内只有密文，恢复码不落盘不上云）。
- 恢复流程（仅需恢复码 + 新设主密码）：
  1. 用户输入恢复码 + 新主密码。
  2. 用恢复码派生信封密钥 → 解密信封 → 取回 MK。
  3. 用新主密码重新派生新 MK'（新 salt）→ 用 K_data' 重加密全部条目/索引
     （数据重加密在后台进行，进度可见）；审计密钥切换走轮换验证链：先用旧
     K_audit 签名一条「审计密钥轮换」事件（记录切换时间与新旧密钥标识），
     再启用 K_audit'（见 [audit.md](audit.md) §3.1）。
  4. 重新生成恢复码 → 用新恢复码派生 K_recovery' 加密 MK' 生成新信封；旧信封
     作废。
- 无恢复码场景：仅主密码 → 只能「重置为新库」（旧数据不可解密），UI 明示。

## 4. 已信任设备宽限（D9，借鉴 1Password 生物识别宽限）

- 目的：日常解锁免输主密码（如 Windows Hello / macOS Touch ID），不降安全。
- 机制：
  - 首次生物识别解锁需主密码授权（建立信任）。
  - 宽限窗口内（如每次解锁后 5 分钟，或系统未重启），生物识别可直接解锁；
    超时/重启后需主密码或恢复码。
  - 设备信任记录本地保存（平台安全存储），随锁定失效不擦除。
- 边界：宽限不替代主密码/恢复码；仅加快已信任设备上的常规解锁。

## 5. 实施注意（M0 起）

- 恢复码生成与校验用 CSPRNG；展示页禁止截图外泄提示（UI 文案）。
- 信封密钥派生参数独立于主 KDF（各自 salt），互不耦合。
- 属性测试：信封往返（恢复码 → MK 一致）；错误恢复码 → 解密失败；
  主密码重置重加密后旧密钥无法解密新数据。
- 安全专项（[testing.md](testing.md)）：恢复码熵检测、暴力猜测速率限制。
