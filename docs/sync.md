# 同步与变更发现规格（sync，M1）

- 状态：已拍板（D7）
- 关联：[data-model.md](data-model.md)（revisionDate/墓碑/CAS）· [ipc.md](ipc.md)（守护进程）
  · [cli.md](cli.md)（`lk sync`）

## 1. 形态：BYO 存储，无服务器

- 同步目标是用户自备（BYO）的无服务器存储：**WebDAV / S3**（含兼容实现）。
- 没有我们托管的中继/推送服务；这是 V1 形态（服务端能力推迟，见
  [architecture.md](architecture.md) 非目标）。
- 存储端零知识：只见密文文件 + 文件名时间戳（D6，见 [data-model.md](data-model.md) §2）。

## 2. 变更发现：加密索引 + 轮询（D7）

- **无推送**。客户端通过**轮询加密索引**发现远端变更。
- 轮询默认 **60s**，可配置范围 **15s ~ 24h**（`lk config`，见 [cli.md](cli.md)）。
- **静默轮询**：后台进行，不打断用户操作；UI 不显示中间加载态。
- **无中间态加载**：轮询只下载「加密索引」，比对后**仅下载发生变更的条目**；
  不整库拖拽。
- 变更比对依据：索引中的 `revisionDate` + `deleted`（见 [data-model.md](data-model.md) §6）。

### 2.1 轮询协议（每轮）

1. GET 远端 `index.lk`（加密）→ 本地解密 → 对比本地索引。
2. 若无差异 → 本轮结束（不下载任何条目）。
3. 若有差异 → 按 id 拉取差异条目的密文文件（含墓碑），解密合并，
   走 CAS 收敛（见 [sync.md](sync.md) §4）。
4. 更新本地索引与 `revisionDate` 水位。

### 2.2 真实的代价（诚实文档，D7）

> 方案 A（完全自研、无托管服务）在 **BYO 无推送存储**下的真实代价是：
> **变更发现只能靠轮询**——默认 60s 的延迟意味着「多端一致性在秒级到分钟级
> 之间」，无法做到推送式即时同步；同时每轮轮询产生一次索引读取流量。
> 这是「没有我们的服务器」的必然取舍，不是缺陷：零知识、零信任、
> 无运维依赖换来了可接受的同步延迟。付费边界中「远程审批中继」等
> 服务端能力（若未来出现）也不改变本设计——轮询仍会是 BYO 场景的默认路径。

## 3. 上传：CAS + last-write-wins（D5/D7）

- 上传携带 base revision（客户端上次见到的该条目 revision）。
- 存储端条件写：WebDAV 用 `If-Match`/ETag；S3 用条件写（`If-Match`）；
  校验失败 → CAS 冲突（见 [data-model.md](data-model.md) §4.3）。
- 冲突收敛：**整条目 last-write-wins**（revisionDate 更晚者胜）；
  V1 不做字段级合并（留口，见 [data-model.md](data-model.md) §4.3）。

## 4. 墓碑收敛（D5/D7）

- 删除在多端传播：墓碑参与同步；对端看到墓碑 → 本地置删除态（可见性：
  回收站/隐藏列表），并参与 30 天硬删计时。
- 硬删需「本端墓碑 ≥ 30 天 且 已同步确认」；硬删文件在远端与本地同时清除。
- 收敛不变量（property test，见 [testing.md](testing.md)）：任意多端同步任意次，
  最终所有端条目集合一致（最终一致）。

## 5. 失败与恢复语义

- 任何一步失败（网络/存储 4xx/5xx）：本轮放弃，保留本地状态，下一轮重试；
  不产生半写状态（先写临时文件 + 原子改名）。
- 首次同步 / 索引丢失：全量拉取（按索引重建），不阻塞解锁（条目可离线使用，
  同步在后台进行）。
- 冲突风暴保护：单轮批量差异过大时退避轮询频率（指数退避至配置上限）。

## 6. 安全约束

- 同步只在**已解锁**守护进程会话中进行（[ipc.md](ipc.md)）；锁定即停止轮询。
- 凭证（WebDAV 账号密码 / S3 密钥）由系统钥匙串/凭据库保管，不进 vault 密文、
  不进审计明文、不落日志。
- 索引与条目密文被篡改 → 解密失败 → 报「同步数据异常」，不自动覆盖本地。
